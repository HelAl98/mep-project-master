# Interface map and integration boundaries

`assets/config/skill-routes.json` registers all 15 skills, paths relative to the configured sibling root, purposes, input/output types, kinds, actual inspected commands/functions, Python and skill dependencies, upstream prerequisites, SQLite requirements, stages, usage/skip conditions and limitations. Runtime discovery adds actual installation paths, missing dependencies/interfaces, availability and source fingerprints. It never assumes existence from the inventory list alone.

The master runtime uses the standard library. Child CLIs use the interpreter that launched the master, ensuring Codex's resolved local dependencies are consistent. Module presence is checked without importing the skill implementation during discovery; presence does not establish a compatible package version. Do not automatically pip install or use external/cloud services. Native DWG/OCR are not silently substituted.

`interfaces.py` translates a restricted task specification to the actual inspected argparse interface. Registry global sibling-root comes before the subcommand, DB/project flags after it. Matcher/reviewer/generator global DB/project/config flags come before the subcommand. PDF/drawing/specification/QC scripts take positional input; their master operation names are not passed as invented subcommands. Original DDC Markdown snippets have no importable API and require Codex instruction workflow/checkpoints. No shell execution, dynamic function-name eval, Markdown exec or Python-to-Codex agent spawning exists.

Optional model-aware assistance uses the native project `.codex/agents/` definitions under [delegation policy](delegation.md). That reference maps the existing 16 skills and 11 stages without replacing these route files. The main Codex agent dispatches only authorized bounded reasoning; child results return to it for validation and parent-owned persistence. Manual/delegated/single-agent policy is separate from Guided/Automatic stage progression. No Python API/model invocation, new CLI command, second workflow engine or database writer was added. Native project configuration loading and explicit-model tool fallback are distinguished in that reference; neither was tested by spawning agents during this update.

The stage DAG does not itself supply project facts. First intake can run deterministically, then actual file IDs/sheet headers/source scopes configure subsequent tasks. `@task-id` passes the checked primary output. SQL handoff uses real extraction run IDs returned by ETL; reviewer/matcher adapters reuse exact existing runs. Multiple views/runs require explicit selection. Source byte hashes remain original-document hashes, not transport JSON hashes.

Read-only project queries use SQLite URI `mode=ro` and query_only. They do not call Registry/Matcher/Reviewer constructors, whose query paths can create tables or derived revisions. Technical record/readiness queries reuse the existing generator `Repository` facade over inspected Registry/Matcher/Reviewer projection interfaces. The facade and `planning.plans` are actual upstream code, not recreated here. They require core 2 and registry/equipment/technical migration 1. This private-API compatibility is provisional and fails visibly on missing/upgraded interfaces.

The master owns orchestration integrity checks only. The QC skill checks supplied evidence packages, not a DB. The master adds read-only structural checks and saves their JSON artifact with the stage event. It never normalizes new engineering values, extracts new equipment facts, writes conflicts into an invented engineering schema or approves discrepancies. Exact originals, source relationships and reviewed decisions remain upstream.

Cross-system isolated execution has a real upstream limitation: matcher match/group and reviewer map/compare operate on project-wide current records, not a system selector. The master permits them in system scope only when the shared DB contains no out-of-scope equipment/specification imports; otherwise it blocks and identifies the unsupported capability. Conservative historical imports may also trigger this guard. Queries/packages can select exact equipment entities; categories must be actual ones. Do not represent a system config label as a filter that the CLI never supports.

Document generation is performed by the existing package generator wherever possible. Original DDC document skills provide conventions for requested supplemental artifacts. Built-in document/spreadsheet/PDF skills own actual authoring/rendering/visual verification for those supplemental artifacts. The master neither runs the defective PDF split/bookmark examples nor installs a replacement extraction skill. Package generation success is separate from visually validated document delivery.
