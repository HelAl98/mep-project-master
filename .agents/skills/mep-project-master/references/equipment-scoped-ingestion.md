# Equipment-only scoped ingestion

This additive mechanism does not modify the eleven stages, specialist skills or engineering approval gates. It audits prepared CAD and native XLSX equipment evidence, then allows the existing matcher JSON intake operation only. It never runs match/group, starts a formal stage, completes Stage03–05 or broadens full-source coverage.

Use scripts/master.py --config <project-config> equipment-scope --receipt <receipt> to record schema mep-equipment-scope/1 in existing master_operator_events. Required envelope: project_id, scope_id, actor, reason, engineering_approval=false; allowed_operation=06:mep-equipment-matcher.import-json; full_source_coverage=false; technical_findings_promoted=false; limitations; context_limitation_ids; items. Actual human continuation acceptance must explicitly allow this operation. Append a new accepted-source-limitation receipt when authorization scope changes; never rewrite prior acceptance.

Each item supplies original {file_id,sha256}, package {path,sha256}, role (drawing/schedule/electrical/bms), stable slot, allowed_disciplines, retained_warning_digest and warning_policy=retain_all_unreviewed_no_coverage_claim. Warning digest is common.key(warning_inventory(package)). All warnings remain in native packages and SQL. Intake may remain partial; this is not a successful full extraction or engineering verification. Unknown physical-instance and quantity flags cannot become true.

CAD provenance supplies kind=cad and path/SHA descriptors for rows, dxf, workbook, conversion and optional supporting_artifacts. The original live/archive bytes, native conversion original/export relationship and artifact hashes must match. Records must link exact native row, handle/layer, text/tag and native coordinates. Schedule parameters must link raw CAD source cells and printed unit evidence. Explicit quantities additionally require quantity_proofs[{record_index,cell,header_native_row_index}]. cell has native_row_index,handle,raw_text,worksheet_row,coordinates. Quantity headers and values must be observed; rows do not imply quantity one.

For native registered XLSX, kind=xlsx plus per-record cell_bindings[{record_index,fields:{tag:<cell>,quantity:<cell>,...}}] permits scalar tag/quantity/description/floor/room fields and no technical parameters. Actual source sheet and row are required; formulas and legacy XLS remain blocked. Richer tabular fields require a supported explicit adapter rather than guessed mappings. BOQ intake is not covered by this contract.

Registering a receipt refuses overlapping file/handle/tag observations across views and duplicate source/slots. Keep one intentional role/slot per source view. A richer schedule and the same annotation rows must not both be ingested as independent evidence.

Create a request per item: {project_id,scope_id,operation,receipt_id,item_index}. A plan has the standard envelope, jobs and result_path. Each job has id, skill=mep-equipment-matcher, command=import-json, one source_file_ids entry, one exact package inputs entry, scoped_request path and options {file-id,role,slot} matching its audited item. Invoke equipment-execute --plan <path>. It uses the existing master lock, adapters, run_job, source/persisted-reference checks and matcher transactional interfaces. It validates all requests before writes and preserves independent successful imports on failure. Job events identify native Stage06 intake work; no formal Stage06 event is created and matching is not authorized by this command.

Native matcher first use installs its shipped equipment migration 1 and triggers in the same engineering schema 2 database; this is existing skill behavior, not a custom schema. Back up the database and adjacent evidence archive before execution. No specialized skill/migration is edited. Native import status partial and issues remain unchanged. The scoped result validator only accepts matching original/role/slot, retained issues and exact persisted raw records. Without this exact scoped receipt the original strict validator remains in force.

Original-source inventories, registry heads, changed/retired limitations and artifact hashes invalidate affected eligibility. The same explicit compatible-master Stage01/02 revalidation contract applies after an implementation fingerprint change. Do not re-extract or reingest old specification evidence. Formal stage states remain truthful. Stage06 matching still requires its existing prerequisite and an explicitly selected dataset/configuration; this import-only operation does not grant matching readiness.
