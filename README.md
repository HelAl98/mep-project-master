# MEP Project Master

A source-traceable MEP assistant with **one master skill, 15 supporting skills,
and six optional native specialist definitions**. It prepares mechanical
procurement for tagged equipment and untagged materials, links specifications
and source evidence, identifies conflicts, and persists field-level decisions
in SQLite before exporting Excel and Word. The Main Agent handles setup and
execution; users resolve material choices and confirm the scope for issue.

## Start

Open this repository in Codex and select `.agents/skills/mep-project-master/SKILL.md`.
Use a separate folder for each engineering project's sources/state/output.
Request: "Prepare mechanical procurement for the project at [path]. Continue
independent work, present conflicts and decisions, and deliver Excel and Word
for review. Issue the selected scope only after my confirmation."

Codex resolves its bundled Python runtime. For standalone deterministic tools,
use Python 3.11+ and install the tested packages with `python -m pip install -r
requirements.txt`. Native roles are optional and require host/model access; the
Main fallback is supported. No API key or external orchestration service is needed.
Do not copy this repository's `.codex/config.toml` over a personal global config.

For a global skill installation, copy the 16 directories under `.agents/skills/`
to the selected user's `~/.agents/skills/`, backing up existing versions first.
Keep the directory names and sibling layout. Native roles use repository-relative
instructions; if installing roles globally, resolve those instruction paths for
the destination instead of replacing existing global roles blindly.

## Focused execution checks

Run from the repository with writable fixture/output paths outside it. These
are synthetic assertions, never real engineering approvals. The fixture folder
must not already exist on the first invocation.

```sh
python -X utf8 -B .agents/skills/mep-project-master/scripts/tests/test_procurement_flow.py --fixture ../mep-fixture --outputs ../mep-samples
python -X utf8 -B -m unittest discover -s .agents/skills/mep-project-master/scripts/tests -p test_procurement_items.py
```

The integration check covers 37 m versus 40 m within the configured tolerance,
370 m versus 40 m flagged, 36 m with missing drops marked partial, original BOQ
retention, header units, field choices after resume, unresolved scope blocked,
explicit exclusion, SQLite reuse, and actual XLSX/DOCX contents. See the test
and [drawing contract](.agents/skills/mep-project-master/references/boq-drawing-checks.md).
The sample source files are generated by the test; real project files and databases
are deliberately absent from the source package.

## Limits

- Verified geometry route: calibrated ASCII DXF model-space LINE centerlines only.
  Direct DWG, curves/POLYLINE, nested/Xref geometry, sloped 3D and OCR are unsupported.
- Specification rules produce traceable candidates; they do not prove universal
  clause completeness. Missing sources/partial coverage remain visible.
- Scoped procurement issue requires actual human confirmation. It is not complete
  design certification or automatic legacy engineering approval.
- Full legacy Mechanical/Electrical/BMS integration and native model dispatch have
  not been validated end to end. Prior document samples received Office visual QA;
  an automated content check alone does not validate pagination in every environment.
- No n8n, supplier messaging, quotation collection, pricing or purchasing.
- Legacy supplier-draft has optional host-specific spreadsheet rendering; the
  verified procurement XLSX/DOCX path uses the listed Python libraries.

## Repository contents

`.agents/skills/` contains all 16 skills and executable helpers, schemas, mappings,
references and tests. `.codex/agents/` contains six optional native role definitions.
`third-party/` preserves upstream attribution. Read [NOTICE](NOTICE.md) before
redistribution. The source package contains no real project data or credentials.

Setup and tests never publish a repository or communicate with suppliers.
The repository includes the complete 16-skill source bundle; project databases
and private engineering documents belong outside it.
